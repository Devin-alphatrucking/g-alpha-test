# DVN Haul

A cozy delivery-driving game for every age. Chase golden hour, beat the storm, and win over a town of characters who remember how you drive.

**Stack:** Vite + TypeScript, Phaser 3 (game), GSAP (landing page), PHP (AI proxy + optional live feed). No audio or image files: art and sound are generated in code.

## Run it

```bash
npm install
npm run dev -- --port 5180 --strictPort   # http://localhost:5180  (add ?play to skip the landing page)
```

The `/api/*` routes are proxied to Apache (XAMPP) at `http://localhost/dvn-alpha-g/public/api/`. Without Apache or an API key the game still works: characters speak from their built-in memory lines.

## Controls

| Action | Keys |
| --- | --- |
| Drive / brake / reverse | ↑ ↓ or W S |
| Steer | ← → or A D |
| Horn | Space |
| Pause | P or Esc |
| Story dialogue | Space / click to advance, 1 / 2 to choose, Esc to skip |

Touch screens get an on-screen D-pad automatically.

## Deploy to your domain

1. `npm run build`
2. Upload the **contents of `dist/`** to the web root (or a sub-folder such as `/haul/`).
3. For AI lines, give the server your Anthropic key in one of these ways (the key must never be in a public folder):
   - set the `ANTHROPIC_API_KEY` environment variable (best), or
   - copy `config.sample.php` to **`dvn-haul-config.php` in the folder *above* your web root** (e.g. `/home/you/dvn-haul-config.php` when the site is in `/home/you/public_html`) and add the key, or
   - for local XAMPP only: `config.php` in the project root.
4. PHP 7.4+ with cURL is required for `api/chat.php`. `public/.htaccess` (copied into `dist/`) adds compression and caching on Apache.

The game bundle loads only when a player presses Start: landing page ≈ 52 KB gzipped, game logic ≈ 21 KB, Phaser ≈ 340 KB in its own long-cached chunk.

## AI memory & safety

Each character remembers gameplay facts only (deliveries, late runs, crashes, rain/night runs, story choices). The browser sends those facts, never free text or names, to `api/chat.php`, which validates every field against whitelists before building the prompt. Calls are rate-limited per session (30 / 10 min). If the API fails, the local voice lines are used.

## Optional: live Alpha Trucking feed

Create `public/data/live.json` (copy `live.sample.json`) and set `"enabled": true` with real numbers exported from your dispatch system, e.g. by a scheduled job:

```json
{ "enabled": true, "date": "2026-10-14", "deliveries": 128, "onTimePct": 96.5 }
```

The game then shows an "Alpha today" pill and gives a small coin bonus (+1% per 4 real deliveries, max 25%). Leave the file out and the feature stays hidden. `live.json` is git-ignored so real figures are never committed.

## Accessibility

Respects `prefers-reduced-motion` (no camera sweep, shake, flashes or lightning), full keyboard play, focus moves into dialogs and Esc closes them, status messages use ARIA live regions, auto-pause when the tab is hidden, and the sound toggle exposes its state.

## Progression & sharing

- **Paint shop (Garage):** two paints are bought with coins; five more are unlocked by finishing each character's story arc.
- **Daily quests:** three new goals every day (same for everyone, seeded by the date); rewards pay out automatically.
- **Share my progress (Journal):** renders a 1080×1350 card with your stats, chapter and friendships, then opens the native share sheet or downloads a PNG. It contains game stats only.

## Play Rooms (multiplayer)

Private rooms of up to 6 drivers, joined with a 4-letter code or an invite link (`/?room=ABCD`).

- Everyone sees each other's trucks (smoothly interpolated), shares a **convoy goal** (20 deliveries → +100 coins each, paid once per room) and gets a **convoy bonus** (+10% coins per friend online, max +30%).
- **Safe by design:** no free-text chat. Names are generated by the server ("Happy Quokka 42"), reactions are five preset emotes, every number is clamped, and each request needs the id + token issued on join.
- Traffic and pedestrians are simulated locally on each screen (not shared), so cars may differ between players.

**How it works:** `public/api/room.php` stores rooms as small JSON files in the server's temp directory and clients poll about 6 times a second. That runs on any PHP host, but it is meant for small audiences: 100 simultaneous players is roughly 600 requests/second. For a big launch, move rooms to a WebSocket server (Node + Colyseus or similar) on a VPS. The client (`src/rooms.ts`) is the only file that talks to the server, so that swap is contained.

Local dev needs the PHP server running next to Vite: `npm run dev:api` (or the `dvn-api` launch config), which serves `public/` on port 8099 and is proxied as `/api`.

## Ads & earning (off by default)

DVN Haul ships with **no ads**. To enable optional *rewarded* ads ("watch an ad: +coins"), edit `public/ads.config.json`:

```json
{ "enabled": true, "provider": "adsense-h5", "client": "ca-pub-XXXXXXXXXXXXXXXX" }
```

- `provider: "mock"` runs a fake 3-second ad so you can test the whole flow without an ad account.
- `adsense-h5` uses Google's H5 Games Ads (`adBreak` API). It needs an approved AdSense account with Games ads enabled. **That code path is untested**: I had no account to try it with.
- **All-ages safety:** when ads are enabled the game first asks "under 13 or 13+?". Under-13s never load or see ads. Ads are never forced; the player taps the button.
- Before turning ads on you still need to: publish a privacy policy, tell the ad network the site may have child users and use its child-directed / non-personalised setting for the under-13 band, add `ads.txt` at the site root, and check current children's online privacy rules for your countries (e.g. COPPA in the US, the Australian Privacy Act and its Children's Online Privacy Code). This is not legal advice.

Other ways the project can earn, none built yet: a sponsored branded paint or customer from Alpha Trucking or a partner, a "Book a delivery" link on the landing page, or cosmetic purchases (adds payment and child-safety complexity, so plan it carefully).

## Landing page images

`public/shots/world-*.webp` are **real captures of the game** (the same view at 2:00 PM, golden hour, dusk, night and rainy night, 1920x1200). The landing page cross-fades between them as you scroll. To refresh them after art changes, run the game at 1920x1200, freeze the traffic in one scene, set the time of day and weather, and export the Phaser canvas for each frame (`canvas.toDataURL('image/webp', 0.84)`); for the rain frame also draw the `#rain` overlay canvas on top.

## SEO, analytics and launch

Production build with SEO values stamped in (canonical, social tags, sitemap, robots, IndexNow key file):

```bash
SITE_URL=https://your-domain.com CONTACT_EMAIL=you@your-domain.com INDEXNOW_KEY=yourrandomkey123 npm run build
npm run seo:check      # audits dist/ like a crawler would; fails on missing canonicals, bad lengths, broken links...
npm run indexnow       # after deploying: pings Bing/Yandex (needs the same SITE_URL + INDEXNOW_KEY)
```

Without `SITE_URL` the build still works but prints a warning and uses a placeholder domain. Full strategy, keyword map, fast-crawl steps, analytics goals, ads management and launch checklist: [docs/SEO-MARKETING.md](docs/SEO-MARKETING.md).

Optional cookie-less analytics: set `public/analytics.config.json` to `{ "enabled": true, "provider": "plausible", "domain": "your-domain.com" }`. It never loads for players who say they are under 13.
